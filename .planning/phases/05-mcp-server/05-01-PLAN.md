# Plan 05-01: MCP server

**Phase:** 5 - MCP server
**Requirements:** MCP-01..MCP-06
**Branch:** phase-05-mcp

## Goal
A chat client (MCP host) can ask "where did I buy X", "how much did I spend at Y", "what did I
pay for Z over time" against the receipts DB, read-only, authenticated, with every answer
carrying receipt ids and dates so it can be checked.

## Design
- Transport (MCP-01): MCP Streamable HTTP, single endpoint `POST /mcp` on the existing server
  (same deployment/service as API + UI). JSON-RPC 2.0; every POST is answered with one
  `application/json` response (the spec allows JSON instead of SSE), notifications get 202.
  `GET /mcp` (server-initiated SSE stream) returns 405 - the server never initiates messages.
  Stateless: no `Mcp-Session-Id`. Methods: `initialize`, `notifications/initialized`, `ping`,
  `tools/list`, `tools/call`. Protocol versions 2025-06-18 / 2025-03-26 negotiated.
  Batches rejected (removed in 2025-06-18). Body capped at 1 MiB.
- Hand-rolled (~300 lines) instead of an SDK: no new dependency, go 1.23 toolchain kept.
- Auth (MCP-03): `Authorization: Bearer <MCP_TOKEN>` (constant-time compare). MCP_TOKEN unset ->
  the endpoint is not mounted at all (fail closed). 401 with `WWW-Authenticate: Bearer`.
  Origin header, when present, must match the Host (DNS-rebinding guard from the spec).
  Token never logged. OAuth 2.1 (MCP authorization spec) deferred - open question.
- Read-only (MCP-01, Out of Scope "write tools in MCP"): repository `QueryRepository` runs only
  SELECTs, each in a `READ ONLY` transaction.
- Which receipts count: status parsed, needs_review or reviewed (uploaded/parsing/failed have
  no trustworthy data). Each answer carries the receipt status. Returns excluded (is_return)
  from where-bought/price history, as in product_purchase_locations_view.
- Merchant inputs (MCP-04/06): `models.NormalizeMerchantName(input)` -> exact match on
  merchants.name, then merchant_name_redirects (merged-away names). No exact match ->
  tool returns `isError` with ranked `candidates` from pg_trgm `similarity(name, key)` (GIN index
  from 006); never auto-picks a fuzzy match.
- Tools (all results carry receipt ids + dates, MCP-02):
  - `list_merchants` (MCP-05): name, receipt_count, last_visit, total_spent_cents, last_receipt_id.
  - `search_products`: canonical name/alias search (existing SearchProducts) + last purchase
    receipt id/date per product.
  - `search_purchases`: line items whose name/raw text/product name contain the query; optional
    merchant, date range.
  - `where_bought`: product_id -> merchant + store location + date + price + receipt id.
  - `spend`: total over optional merchant/date range, grouped by merchant or month, with the
    receipt ids in each group.
  - `price_history`: product_id (optional merchant) -> unit price per purchase, oldest first.
- Limits: every list tool takes `limit` (default 50, max 200); result says `truncated`.
