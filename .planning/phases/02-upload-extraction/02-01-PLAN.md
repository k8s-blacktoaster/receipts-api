# Plan 02-01: Photo upload + extraction pipeline

**Phase:** 2 - Upload + extraction pipeline
**Requirements:** ING-01, ING-02 (local disk now; object store in phase 6), ING-03, ING-04, ING-05
**Branch:** phase-02-upload-extraction

## Goal
A JPEG/PNG phone photo POSTed to the API becomes a stored source document plus a receipt that a
background worker moves uploaded -> parsing -> parsed | needs_review | failed, using a pluggable
vision-LLM provider (Grok/xAI default). No live API calls in tests.

## Design
- **Migration 007** (paired down): receipts.merchant_id/date nullable while
  uploaded/parsing/needs_review/failed (CHECK receipts_complete_when_parsed); unique
  receipts.source_document_id (one receipt per photo); partial index on pending receipts;
  source_documents.parsed_at. Down is lossy (deletes receipts without merchant/date).
- **Storage** `internal/storage`: BlobStore {Put, Get}; Local (UPLOAD_DIR, atomic write,
  key = receipts/<sha[:2]>/<sha256>.<ext>, path-traversal guard); Memory for tests.
- **Upload** `POST /api/v1/uploads` (multipart `image`, optional `uploaded_by_id`, `member_id`):
  sniffed type must be image/jpeg or image/png (xAI accepts these), max 20 MiB (MAX_UPLOAD_BYTES).
  SHA-256 dedupe -> 200 with the existing receipt; else blob + source_document + receipt
  (source=photo, status=uploaded) in one transaction -> 202 and enqueue.
  `POST /api/v1/receipts/{id}/extract` re-queues a photo receipt.
- **Provider** `internal/extraction`: `Provider{Name, Model, Extract(ctx, []Image) (*Result, error)}`.
  - xAI: POST {XAI_BASE_URL}/chat/completions, Bearer XAI_API_KEY, model EXTRACTION_MODEL
    (default grok-4.20), temperature 0, image as base64 data URL (detail high), system prompt,
    response_format json_schema strict (all fields required, nullable where unknown).
  - Anthropic: stub returning ErrNotImplemented. `none` disables extraction.
  - Selection: EXTRACTION_PROVIDER = xai (default) | anthropic | none.
- **Mapping**: extraction JSON -> models.Receipt; printed merchant kept in store_name, merchant
  resolved by models.NormalizeMerchantName; items keep sku/item_number/upc; money in cents with
  the phase-1 sign convention (item discount/savings positive, reducing adjustments negative).
- **Check**: required merchant (normalizes to non-empty), valid date, subtotal, total, >=1 item;
  total must match subtotal+tax-savings, subtotal+tax+adjustments, or subtotal+tax within
  EXTRACTION_TOLERANCE_CENTS (default 2). Any reason -> needs_review with parse_error = reasons.
- **Pipeline**: set parsing (parse_started_at) -> load blob -> provider -> map -> check ->
  Update receipt + children -> status parsed|needs_review (parsed_at) -> save raw JSON/model/
  prompt version on source_documents. Provider/blob/save errors -> failed + parse_error; the
  receipt's previous fields are not overwritten on provider failure.
- **Worker**: in-process queue (EXTRACTION_WORKERS, buffered); on start, re-queue receipts left
  uploaded/parsing. Durable state is receipts.status (no jobs table yet; see open questions).
- **Secrets**: XAI_API_KEY only from env (k8s Secret -> env). Never logged; errors truncated and
  checked not to contain the key. Missing key -> uploads still accepted, extraction disabled.
